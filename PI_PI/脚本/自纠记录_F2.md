## `F-6`：T3 结论层的两处自相矛盾（2026-09-28 新增）

**错误 1 — 基域选错，判据自我否定**

初版写「`u` 与 `ln π` 在 `ℚ(π,e,lnπ)` 上代数无关」。
但 `π` 本身就在基域内，故 `(π, ln π)` 在该基域上**天然相关**
（见证多项式 `X − π`）。该判据会把表格中标为「配方适用」的 `u = π`
**一并排除** ⟹ 判据与表格直接冲突。

**正确判据**：`(u, ln π)` 在 **`ℚ`** 上代数无关，
即不存在非零 `P ∈ ℚ[X,Y]` 使 `P(u, ln π) = 0`。
（该条件自动蕴含 `u ∉ ℚ`：若 `u = p/q` 则 `P = qX − p` 即反例。）

**错误 2 — `e^e`, `e^π` 被无依据列为「立即可证可用」**

初版称「立即可证可用: `u ∈ {e, π, π², e^e, e^π, ...}`（由步 2 逐步扩张）」。
步 2 只给出 `π, ln π, e` 代数无关，它能担保的 `u` 是
**`π, e` 的非常数有理系数多项式**（无穷集），例如 `e, π, π², π·e, e+π, …`。

`e^e` / `e^π` **不是** `π, e` 的多项式。要用配方须先证
`e^e` 在 `ℚ(π,e,lnπ)` 上超越，而 **`e^e` 的无理性至今未证**
（arXiv:1310.7289 摘要明列 `e^e` 属「连无理性都未知」之列）。
⟹ 正确标注为 **`【未知】`**，既非「可用」也非「需额外 `(S)` 应用」。

**教训**：结论层的集合描述必须与**表格逐行一致**。
两张表打架时，说明**判据写错了**，而不是某一行特例。
（与 `F-2g` 同类：`chk` 判据方向用错但输出看似正常。）

**`F-2` 系列共同的严重性**：三处缺陷叠加后，T2 曾以
`[PASS] 排除所有分母 <= 10^16 的有理数` 的形式输出**未被证实的结论**。
若当时未复查，**一个假定理已进入项目文档**。
这直接触发 P4 §14.3 `L0 熔断` 的判定标准：
**结果显著但缺乏独立复现依据** → 全部相关结论标记「待复核」。

## `F-2a`：精度设置落到了错误的 context

```python
import mpmath as mp
mp.mp.dps = 60          # ← 无效
mp.dps = 60             # ← 也无效: 这是给【模块】加了个名为 dps 的属性
```

- `mp.mp.dps`：改的是另一个 context，与全局计算无关。
- `import mpmath as mp; mp.dps = 60`：mpmath 模块**没有** `dps` 属性，
  该赋值只是新建了一个普通模块属性，**完全不影响计算**。

**正确写法**：

```python
from mpmath import mp     # 拿到真 context
mp.dps = 60
```

**为什么危险**：脚本第一版 `pipi_schanuel_chain.py` 用了
`mp.mp.dps = 60`，其 PSLQ 与常数打印**实际运行在默认 15 位精度**下，
而输出看起来完全正常。该脚本结论已在新一轮中以真 context 复跑验证。

**审计规则（已落进 `pipi_gap1a_test.py`）**：
不允许只检查 `mp.dps` 的值，必须用**与精度无关的方式**验证：

- 守卫 A：与 100 位 π 字面量逐位比对前 40 位；
- 守卫 B：`dps=60` 与 `dps=120` 两次独立计算须在 50 位上一致。
  若真实精度只有 15 位，二者必在第 15 位分叉。

## `F-2b`：`float()` 抹掉区间宽度 → `delta = 0`

```python
lo = float(ivX.a)      # iv.mpf 是区间对象
hi = float(ivX.b)
delta = hi - lo       # ← 端点仅差在第 100 位, float 只有 16 位 → delta = 0.0
```

`delta = 0` 使「残差 > delta」**恒真**，于是
`[PASS] 排除所有分母 <= 10^12` 被无理由报出。

**正确做法**：全程用 `fractions.Fraction` 承载区间端点，
判据用**真实宽度**而非 float 近似。

## `F-2c`：判据用错了宽度

修正 `F-2b` 时，一度把「外扩量 `eps`」当作误差界：

```python
lo = Fraction(s_lo) - eps        # eps = 1e-117, 仅为防打印舍入
strict = r > eps                # ← 错: eps 不是计算误差
```

真正需要比较的是 `r > W/2`，其中 `W = hi - lo` 是**区间实际宽度**。
用 `eps` 会把「不可判定」误判为「已排除」。
同一 bug 在改用真 context 后一度仍残留（见 `F-2d` 的排查过程）。

## `F-2e`：`iv.dps` 默认仅 15 位

`iv.prec` 会被 `iv.dps` 覆盖；`iv.dps` 未显式设置时**默认 15**。
设 `iv.prec = 2000` 不产生任何效果，实测区间宽度只有 `~1e-15`。
最终用 `iv.dps = 120`，实测 `W ≈ 2.06e-117`，与 250 位独立重算一致。

## 审计清单（后续脚本强制项）

1. 精度设置后必须有**与精度无关**的守卫（两位一致 / 字面量比对）。
2. 区间端点禁止经过 `float`；用 `Fraction` 或 mpmath 高精度类型。
3. 判据必须用**真实误差界**（区间宽度），不得用外扩余量代替。
4. 区间算术结果必须由**独立路径**交叉验证（不同精度 / 不同算法）。
5. 任何 `[PASS]` 若来自「未命中」，须区分「已证不存在」与「未搜索到」；
   前者需理论论证，后者只能是 `EMPIRICAL`。
6. 判据方向须逐项复核：区分「预期通过」「预期失败」「不可判定」，
   不可判定项**不计入失败也不计入通过**。
